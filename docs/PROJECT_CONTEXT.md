# kanc-control: контекст проекта

Внутренняя информационная система сети филиалов (продажа флешек, фотосалон,
услуги ЕГОВ). Роли: ADMIN (администратор) и SELLER (продавец, привязан к филиалу).

## Стек и версии

- Next.js 16.4.3 (App Router, Turbopack, включены Cache Components), React 19.3.0
- Node.js 22, **JavaScript** (не TypeScript), алиас `@/` указывает на `src/`
- MySQL, Prisma 7.10.1 с драйвер-адаптером `@prisma/adapter-mariadb` (пакет `mariadb`)
- Bootstrap 5.3.8
- Аутентификация: `jose` (подписанная cookie-сессия), `bcryptjs` (хеши паролей),
  `zod` (валидация), `server-only` (защита серверных модулей)

## Особенности Prisma 7 (важно)

- Адрес БД задаётся в `prisma.config.ts`, а не в `schema.prisma`.
- Для команд Prisma CLI (migrate, studio) используется `MIGRATION_DATABASE_URL` (root);
  приложение и seed используют `DATABASE_URL` (пользователь `kanc_app`).
- Клиент создаётся через адаптер в `src/lib/prisma.js` (один экземпляр на приложение).
- Опция `allowPublicKeyRetrieval` включена только для localhost.
- После изменения схемы: `npx prisma migrate dev`, затем `npx prisma generate`.
- Seed: `npx prisma db seed` (файл `prisma/seed.mjs`).

## Права MySQL

- `kanc_app`: только SELECT, INSERT, UPDATE, DELETE на `kanc_db`. Менять структуру БД нельзя.
- `root` без пароля: только для локальных команд Prisma CLI.

## Структура и ключевые файлы

- `src/lib/prisma.js`: клиент БД
- `src/lib/session.js`: создание, чтение, удаление сессии (cookie `session`, 8 часов, httpOnly)
- `src/lib/auth.js`: `getCurrentUser()` (роль берётся из БД), `requireUser()`, `requireRole(...)`
- `src/lib/rate-limit.js`: ограничение попыток входа (в памяти, 5 попыток на 15 минут)
- `src/app/login/`: вход (`actions.js`, `LoginForm.js`, `page.js`)
- `src/app/actions/auth.js`: выход
- `src/app/admin/`: панель администратора, `admin/users/new`: создание продавцов
- `prisma/seed.mjs`: роли и первый администратор (логин и пароль берутся из `.env`)

## Переменные окружения (значения НЕ хранить в репозитории)

`DATABASE_URL`, `MIGRATION_DATABASE_URL`, `SESSION_SECRET`,
`SEED_ADMIN_USERNAME`, `SEED_ADMIN_PASSWORD`

## Правила разработки

1. Каждая защищённая страница и **каждое серверное действие** начинаются с
   `requireRole(...)` или `requireUser()`. Скрытия кнопок недостаточно.
2. На страницах, читающих данные пользователя, ставится `export const instant = false`
   (после появления общего layout группы `(app)` переносится в него).
3. Роль пользователя всегда берётся из БД, роль из формы не принимается.
4. Данные продавца всегда фильтруются по `user.branchId` на сервере.
5. Все входные данные проходят проверку через `zod`.
6. Пароли только в виде bcrypt-хешей, `passwordHash` никогда не отдаётся на клиент.
7. Миграции только безопасные (добавление столбцов и таблиц), без удаления данных.
8. Не добавлять библиотеки без объяснения необходимости.
9. Секреты не попадают в код, Git и сообщения.

## Принятые решения

- Аутентификация: подписанная cookie-сессия на `jose`, без таблицы сессий (вариант C).
- Регистрация «с улицы» отсутствует: продавцов создаёт администратор.
- Восстановление пароля: сброс администратором (временный пароль + обязательная смена),
  email и почтовые ссылки не используем. Пароль администратора восстанавливается скриптом на сервере.
- Отчётность фотосалона и услуг ЕГОВ: сотрудник вводит 4 числа: наличные, безналичные,
  услуги, товары. Сервер проверяет, что наличные + безналичные = услуги + товары = общая сумма.
  У филиалов с продажей товаров (флешки) остаются остатки и брак.
- Тип филиала определяет, какую форму отчёта видит сотрудник.
- Дизайн: подробные требования в `docs/UI_REQUIREMENTS.md` (mobile-first, Bento Grid,
  палитра Navy/Teal, Bootstrap + CSS-переменные). Продавец: нижняя навигация на телефоне;
  администратор: боковая панель на компьютере. В меню только существующие разделы,
  фиктивных данных нет.
- Оформление: переменные палитры `--kc-*` в `src/app/globals.css`, привязаны к Bootstrap.
  Шрифт Inter (латиница и кириллица). Кнопки и ссылки используют `#0F766E`
  (контраст с белым ~5,5:1), акцент `#0D9488` только для иконок и крупных элементов.
  Тёмной темы нет. Иконки (`bootstrap-icons`) подключаем в задаче о навигации.
